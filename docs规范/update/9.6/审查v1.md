\## 二、项目背景（审查基准）



\### 2.1 技术形态



\- \*\*零前端框架\*\*：原生 HTML/CSS/JS 单窗口 SPA，每页一个 `.page` div。禁止 React/Vue/组件库运行时；组件视觉参考 shadcn/ui，交互逻辑参考 antd。

\- \*\*Electron ^44.1.1\*\*，依赖 `setBackgroundMaterial`（Electron 30+）。

\- 运行时 npm 依赖仅 4 个，\*\*默认不新增依赖\*\*。

\- 原生组件 `native-scanner/`（Rust）编译出 `finder.exe`，由 electron-builder 作为 extraResources 进包。

\- 中文 UI，Fluent Design 原生风格，仅供个人测试交流。



\### 2.2 进程架构



| 部分 | 文件 | 职责 |

| --- | --- | --- |

| 主进程 | `main.js`（约 2300+ 行） | 窗口创建、全部 ipcMain.handle、appearance.json 持久化、原生窗口材质、安全模块 SECURITY |

| 预加载 | `preload.js` | contextIsolation + sandbox，白名单暴露 `window.api` |

| 主窗口 | `src/index.html` | 每页一个 `.page` div |

| 子窗口 | models-window / peripheral-window / process-manager-window | 共用 `src/scripts/window-material.js` 同步主题与材质 |

| 预览窗 | preview-window.html | 刻意不加载 window-material.js，保持纯黑底 |



\### 2.3 渲染层脚本职责



| 脚本 | 职责 |

| --- | --- |

| `app.js` | 路由 switchPage、磁盘清理五合一视图、全局初始化；`liquidMotionSelect` 绑定 |

| `theme.js` / `theme-boot.js` | 主题/背景模糊度/预设背景初装；theme-boot 是首帧前外置引导（勿内联回 index.html，CSP 会拦截） |

| `pathbinding.js` | 设置页外观（主题/材质/背景图片+雾化度+背景模糊度/强调色/系统信息折叠）与安装路径绑定 |

| `liquid-glass.js` | 液态玻璃引擎 2.0：`body.lg-mode-full/standard/frost/off` 四档；为 `.filter-tabs/.maint-tabs` 挂 `.lg-thumb` 弹簧滑块 |

| `spotlight.js` | 跟随聚光（仅作用于 `.btn/.filter-tab/.maint-tab/.material-card/.radio-row`） |

| `cleanup.js` / `finder.js` | 磁盘清理主视图 / 重复·大文件·空项·AppData 查找器（finder 按 `\[data-finder-manifest]` 全局绑定清单按钮） |

| `memoryclean.js` | 内存清理页（`#memUseValue` 有 fitMemValue + ResizeObserver + line-clamp 三重护栏） |

| `ds.js` / `ds.css` | 设计系统运行时 `window.ds` |

| `modal.js` | 弹窗/确认框（ds.focusTrap；删除类红色 confirmDanger） |

| `xtable.js` | 表格组件（虚拟滚动、ResizeObserver，返回 relayout/dispose） |



\### 2.4 样式分层



加载顺序 `main.css → ds.css`，后写覆盖先写。分层：



1\. `:root`/`.theme-light` token

2\. `data-skin="glass"`（背景模糊度驱动，`--glass-blur` 0-26px）

3\. 基础组件

4\. 「Trim 2.0 final visual layer」

5\. 拖尾/预设背景/自定义背景图

6\. 「窗口材质 2.0」（`body.electron-mica`）

7\. 「液态玻璃 2.0」

8\. 「窗口界面升级3」

9\. 「设置页整合4」（卡片子分区 `.appearance-sub` 等）



\*\*关键教训\*\*：覆盖层里的字面色（如 `#ffffff`）会让 token 体系失效。改表面颜色必须查两处：token 定义本身 + 文件尾各覆盖层的字面值。



\### 2.5 状态与数据存储



| 位置 | 键 / 字段 | 说明 |

| --- | --- | --- |

| `%APPDATA%\\Trim\\appearance.json` | material / materialEnabled / windowState | 主进程持久化（`SECURITY.atomicWriteJson`） |

| localStorage `winclean-appearance` | accent / bgPath / bgOpacity / bgBlur / presetBg / material / materialEnabled | 渲染层镜像，\*\*与 appearance.json 是两套存储\*\*；bgOpacity 与 bgBlur 均存百分数（0-100） |

| localStorage 其他 | `winclean-active-page` / `winclean-cleanup-view` / `winclean-liquid-motion` / `winclean-systeminfo-open` / `winclean-theme` | 页面记忆 / 五合一视图 / 液态玻璃档位 / 折叠态 / 主题 |



\*\*背景模糊度约定\*\*：0% = 经典不透明面板；>0% 挂 `body\[data-skin="glass"]`，模糊半径 `--glass-blur` = 百分比 × 26px（`GLASS\_MAX\_BLUR\_PX`，pathbinding.js 与 theme.js 两处共用约定，改动需同步）。



\*\*材质值域\*\*：`mica / mica-alt / acrylic / thin-acrylic / none`；链路：渲染层 → IPC `appearance:set-material` / `appearance:set-material-enabled` → 主进程对全部存活窗口 `setBackgroundMaterial` + 持久化 + 广播 `appearance:material-changed`（载荷是\*\*生效材质\*\*字符串，总开关关闭时为 `'none'`）。



\*\*Win11 27H2 红线\*\*：最大化/还原路径禁止任何原生材质操作；`body.win-maximized` 与 `data-material="none"` 必须 100% 不透明。



\### 2.6 清理规则与执行引擎



\- 清理规则唯一数据源是 `src/data/cleanup-rules.json`（P1-9）。

\- 条目目标模型按优先级路由：`special:'dism'` → `fileKeys\[]` → `regKeys\[]` → `pathPs`。

\- `regKeys` value 语义：无=删树 / `'\*'`=清键值 / 具名=删值。

\- 通用字段 `detect\[]`（未命中不参与扫描）、`requiredStoppedProcesses`（扫描出 blockedBy 标签，执行命中即整项跳过）。

\- \*\*改规则 JSON 后必须同步 `cleanup.js` 的 FALLBACK 副本\*\*。

\- 数据目录 `%APPDATA%\\Trim\\cleanup\\rules.json` 优先于内置生效，`custom\\\*.json` 同名 id 覆盖。

\- 更新走 `cleanup:update-rules` IPC（GitHub → jsDelivr → gh-proxy 回退，尺寸/结构/防降级校验，.downloading 原子替换）。

\- `cleanup:execute` 收到 `{items,force,toRecycle,autoRebuild}`；toRecycle 时 PS 只枚举输出 `@@RECYCLE@@` 行，主进程 `shell.trashItem` 实际移入回收站。

\- `cleanup:item-detail` 用 DETAIL\_SCRIPT 只读枚举文件清单（上限 600 行，`@@ITEMFILE@@`/`@@DETAIL@@` 行协议）。



\### 2.7 安全边界（硬性约束）



\- 新增 `ipcMain.handle` 一律 sender 校验 / `rejectUntrustedRenderer`。

\- preload 只做白名单转发。

\- 写 JSON 走 `SECURITY.atomicWriteJson`。

\- 临时脚本只放 `%APPDATA%\\Trim\\tmp\\`。

\- 删除类回收站兜底 + 确认弹窗统一 modal.js。

\- 提权走 `elevate:request` 握手（禁静默提权）。

\- 快捷指令渲染层只发 id，主进程按白名单 spawn。

\- 日志缓冲落盘、危险操作前 `flushLogSync()`、不打印敏感信息。



\### 2.8 交互与视觉规范



\- 主窗口默认并最小 \*\*1294×870（客户区，`useContentSize: true`）\*\*，不允许缩小，可最大化。

\- 独立窗口 `show:false` + `ready-to-show` 首帧后才显示 + 主窗口 `backgroundThrottling:false` + `window.api.window.notifyFirstPaint()` 握手——都是黑闪修复的一部分。

\- 磁盘清理分类默认折叠；删除类确认走 modal.js 红色 `confirmDanger`。

\- 设计系统硬性约束：只用 main.css 既有 token；圆角 ≤ 8px（胶囊/徽章除外），禁大圆角与彩色渐变；`prefers-reduced-motion` 下无动画；文本 API 一律转义禁拼 HTML；悬停提示用 `data-tip` 不用原生 title。



\### 2.9 已知回归陷阱（审查时重点验证是否被破坏）



1\. `liquid-glass.js` 的 `schedulePlace` 会 cancel 前一个 rAF——`app.js` setCleanupView 里 `refreshAll(animate)` 必须是 `true`。

2\. quickcmds / maintenance 分类栏 innerHTML 整体重渲染 → 滑块走 MutationObserver 路径。

3\. finder.js 按 `\[data-finder-manifest]` 全局绑定、其余按钮靠 id 通信——\*\*别改 id / data 属性\*\*。

4\. 内存卡 `#memUseValue` 三重护栏，动 summary-value 结构前先看 memoryclean.js。

5\. 液态玻璃性能护栏是刻意的：折射元素上限 28、>420px 大元素只磨砂、位移贴图缓存 48、rAF 节流——不要放开。

6\. ds.js 未加载时相关功能必须优雅降级。

7\. PS 里属性缺失时 `@($null).Count` 是 1（判空要先 `-not $x`）；哈希表 `$m.count` 命中内建 Count 属性，要用 pscustomobject。

\## 三、审查维度



请按以下 \*\*8 个维度\*\* 逐项审查，每个问题必须标注：\*\*问题位置（文件+行号/函数名）、严重等级（🔴严重 / 🟡中等 / 🟢建议）、问题描述、根因分析、优化方案（含代码示例）\*\*。



\### 维度 1：安全漏洞审查



\- IPC 通道是否存在未校验 sender 的 handle？

\- preload 暴露的 API 是否有越权风险？是否存在原型链污染面？

\- PowerShell 脚本拼接是否存在命令注入？用户输入/路径是否经过转义？

\- 清理规则在线更新的校验链是否完整（尺寸/结构/防降级/签名）？

\- `shell.trashItem` / 文件删除路径是否有路径穿越风险？

\- 临时脚本目录是否有清理机制？是否可能被劫持？

\- 日志是否可能打印敏感信息（路径含用户名、token 等）？

\- CSP 配置是否足够严格？是否有内联脚本绕过？



\### 维度 2：架构与可维护性



\- `main.js` 2300+ 行是否存在上帝对象？是否应按域拆分模块？

\- 渲染层脚本之间是否存在隐式依赖（加载顺序硬编码）？

\- `appearance.json` 与 localStorage `winclean-appearance` 双写是否存在数据不一致风险？是否应有单一数据源？

\- 清理规则 FALLBACK 副本与主 JSON 双源维护是否容易漂移？

\- 子窗口与主窗口的状态同步是否有竞态条件？

\- 错误处理是否统一？是否存在静默吞错？



\### 维度 3：性能优化



\- 液态玻璃引擎的 rAF 节流、元素上限是否合理？是否有不必要的重绘？

\- 窗口材质切换时是否有不必要的全窗口重绘？

\- 内存清理页的实时刷新是否有定时器泄漏？



\### 维度 4：健壮性与边界处理



\- `appearance.json` 损坏/格式错误时是否有降级恢复？

1\. \*\*只审查，不修改\*\*：输出问题与方案，不直接改动代码。
