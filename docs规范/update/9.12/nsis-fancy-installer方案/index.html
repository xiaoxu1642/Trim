Trim 安装器Fancy 重构方案

上一版用 MUI2 默认框架 + 侧边图/横幅做了品牌化，但窗口仍是 NSIS 老派灰白向导。这一版彻底放弃 MUI2 默认布局，用 nsis.script 完全自定义脚本 + 品牌沉浸背景 + 现代控件，打造类似 Discord / VS Code 风格的深色安装体验。

nsis.script 完全自定义 深色品牌沉浸 640×400 大窗口 零新增 npm 依赖 ⚠ 开发成本较高

为什么需要重构

上一版（MUI2 + 侧边图）的天花板在哪里。

MUI2 框架的硬限制

① 窗口尺寸固定约 498×366，无法放大；② 主区永远是白色/浅灰，深色全覆盖需改 MUI_UI 资源；③ 按钮是系统默认样式，无法做渐变/阴影；④ 进度条是经典灰色，无法品牌化；⑤ 页面布局固定（左图右文 / 上横幅下文），无法做沉浸式设计。

Fancy 重构的目标

① 窗口放大到 640×400，信息密度更舒适；② 全窗口深色品牌背景（渐变 + 装饰光晕 + 网格）；③ 自定义按钮（渐变 + 阴影 + hover 微动）；④ 品牌色进度条 + 实时日志；⑤ 欢迎页展示功能亮点卡片；⑥ 完成页展示安装统计；⑦ 与 Trim 应用内深色 Fluent 语言完全一致。

⚠️
前提说明：npm/GitHub 上没有确切叫 "fancy-installer" 的包。本方案按"fancy 风格安装器"的概念，用 NSIS 原生能力（自定义脚本 + MUI_UI 资源 + 自定义页面）实现。如果你指的是某个具体包（如 @painda/wizard），发我链接，我按实际用法调整。

两条技术路线对比

彻底摆脱 MUI2 有两条路，各有取舍。

路线做法优点缺点与现有链路兼容性
A · nsis.script 完全自定义 ⭐推荐 electron-builder nsis.script 指向自定义 .nsi，完全接管安装流程；用 nsDialogs 做自定义页面，MUI_UI 替换控件模板 零新增依赖；与 electron-builder/electron-updater 完全兼容；差量更新不受影响；NSIS 原生稳定 NSIS 脚本开发成本高；nsDialogs 控件能力有限（无真正圆角/透明/动画）；调试靠反复构建 ✅ 完全兼容，differentialPackage 正常
B · @painda/wizard 现代安装器 安装 @painda/wizard，用 TypeScript 配置定义安装流程；它包装 electron-builder 输出，生成基于 Web 技术的自包含安装器 .exe UI 能力极强（HTML/CSS/JS，可做动画/透明/任意布局）；配置简单；现代感拉满 新增 npm 依赖（需你同意）；与 electron-updater 差量更新的兼容性需验证；包较新（2026.6），生态不成熟；安装器体积可能增大 ⚠ 需验证差量更新链路
💡
推荐路线 A 的理由：项目红线"不新增 npm 依赖须先同意"，且 electron-updater 差量更新是已落地的核心功能，不能冒险。路线 A 用 NSIS 原生能力做到 80% 的 fancy 效果，风险可控。如果后续验证路线 B 与差量更新兼容良好，可再迁移。

推荐方案：NSIS 自定义脚本架构

用 nsis.script 完全接管，四个自定义页面 + 品牌资源。

📄 自定义脚本

build/installer.nsi — 完全自定义的 NSIS 脚本，定义四个页面（欢迎/目录/进度/完成），不使用 MUI_PAGE_* 宏。

🎨 界面资源

build/ 下放背景图（640×400 BMP）、按钮图、图标。背景图用深色渐变 + 装饰光晕预渲染，避免 NSIS 运行时绘制。

🔧 electron-builder 配置

package.json 的 nsis.script 指向自定义 .nsi；保留 differentialPackage:true、perMachine:false、artifactName 等功能字段。

json · package.json → build.nsis（核心变更）
"nsis": {
  // 功能字段保留不变
  "oneClick": false,
  "perMachine": false,
  "allowElevation": true,
  "allowToChangeInstallationDirectory": true,
  "differentialPackage": true,
  "deleteAppDataOnUninstall": true,
  "shortcutName": "Trim",
  "artifactName": "${productName}-Setup-${version}.${ext}",

  // ===== 关键：完全自定义脚本 =====
  "script": "build/installer.nsi",

  // 图标复用
  "installerIcon": "src/assets/ico/Trim.ico",
  "uninstallerIcon": "src/assets/ico/Trim.ico"
}
⚠️
注意：使用 nsis.script 后，electron-builder 默认的 assistedInstaller.nsh（含欢迎页/目录页/完成页/快捷方式创建/卸载注册逻辑）全部不生效，需要在自定义脚本里重新实现。这是最大的工作量，也是风险点。建议先基于 electron-builder 默认模板 assistedInstaller.nsh 改造，而非从零写。

核心脚本骨架与资源清单

自定义 .nsi 的关键结构，以及 build/ 目录需要的资源文件。

nsi · build/installer.nsi（骨架，基于 electron-builder 模板改造）
; ===== Trim Fancy Installer 自定义脚本 =====
; 基于 electron-builder assistedInstaller.nsh 改造，保留其安装/卸载核心逻辑
; 仅替换 UI 层：用 nsDialogs 自定义四个页面，背景用图片预渲染

!include "MUI2.nsh"
!include "nsDialogs.nsh"
!include "LogicLib.nsh"

; ===== 品牌常量 =====
!define APP_NAME "Trim"
!define APP_VERSION "2.5.1"
!define BG_IMAGE "buildbg.bmp"  ; 640x400 深色品牌背景

; ===== 窗口设置：640x400，居中，无默认侧边图 =====
!define MUI_UI "trim-ui.exe"  ; 自定义 UI 资源（可选，替换默认对话框模板）
InstallDir "$LOCALAPPDATA\Programs\Trim"
RequestExecutionLevel user  ; perMachine:false 免 UAC

; ===== 自定义页面：欢迎 =====
Page custom CreateWelcomePage LeaveWelcomePage
; ===== 自定义页面：安装目录 =====
Page custom CreateDirPage LeaveDirPage
; ===== 安装进度（NSIS 原生 InstFiles）=====
Page instfiles
; ===== 自定义页面：完成 =====
Page custom CreateFinishPage

; ===== 欢迎页创建（nsDialogs）=====
Function CreateWelcomePage
  nsDialogs::Create 1018
  Pop $0
  ; 背景图（铺满整个客户区）
  ${NSD_CreateBitmap} 0 0 100% 100% ""
  Pop $1
  SetBitmap $1 "${BG_IMAGE}"
  ; 标题文字（白色，大号）
  ${NSD_CreateLabel} 40 50 400 30 "欢迎使用 Trim"
  ; 功能亮点卡片（三个位图按钮或自绘）
  ; ... 省略具体控件创建 ...
  nsDialogs::Show
FunctionEnd

; ===== 安装段（复用 electron-builder 默认逻辑）=====
Section "Main"
  SetOutPath "$INSTDIR"
  File /r "app\*.*"  ; electron-builder 注入的应用文件
  CreateShortCut "$DESKTOP\Trim.lnk" "$INSTDIR\Trim.exe"
  WriteUninstaller "$INSTDIR\uninstall.exe"
SectionEnd

; ===== 卸载段 =====
Section "Uninstall"
  Delete "$DESKTOP\Trim.lnk"
  RMDir /r "$INSTDIR"
SectionEnd

实施步骤与风险控制

建议分阶段落地，每阶段可独立验证，避免一次性大改导致构建链断裂。

1

阶段一：提取默认模板（0.5 天）

从 electron-builder 安装目录找到 app-builder-lib/templates/nsis/assistedInstaller.nsh，复制到 build/installer.nsi 作为基础。先确认用 nsis.script 指向这个复制版能正常构建（功能完全不变），再开始改 UI。

2

阶段二：制作品牌资源（0.5 天）

用设计工具（或本页后续提供的 canvas 生成器）制作 640×400 深色背景 BMP、主按钮三态图。背景图预渲染渐变+光晕+网格，避免 NSIS 运行时绘制。放入 build/ 目录。

3

阶段三：替换欢迎页+完成页（1-2 天）

先用 nsDialogs 重写欢迎页和完成页（这两页不涉及安装逻辑，风险最低），验证背景图、文字、按钮、复选框正常。目录页和进度页暂时还用默认 MUI，确保构建链不崩。

4

阶段四：替换目录页+进度页（1-2 天）

重写目录页（安装路径输入+浏览+快捷方式勾选）和进度页（品牌进度条+实时日志）。进度页用 NSIS 原生 InstFiles + 自定义回调更新进度条文字。验证安装逻辑（文件复制、快捷方式、卸载注册）完全正常。

5

阶段五：MUI_UI 资源微调（0.5 天）

用 Resource Hacker 编辑 MUI_UI 资源，把剩余系统控件（如消息框、浏览对话框）的字体/颜色对齐品牌色。这一步可选，不做也不影响核心体验。

6

阶段六：全链路验收（1 天）

① 真机安装/卸载全流程走通；② 验证 electron-updater 差量更新（从旧版升级到新版，安装器 UI 是否正常）；③ 验证 perMachine:false 免 UAC；④ 验证快捷方式创建/删除；⑤ 验证 deleteAppDataOnUninstall。全部通过后提交发布。

⚠️
核心风险：① nsis.script 完全替换后，electron-builder 的 differentialPackage 差量更新依赖默认模板的特定结构，自定义脚本可能破坏差量包生成——必须在阶段一就验证差量包是否正常；② nsDialogs 控件无圆角/透明，视觉还原度依赖图片预渲染；③ NSIS 脚本调试只能靠反复构建（每次 2-3 分钟），开发效率低。建议：先做阶段一验证差量更新，若差量包异常则回退到上一版 MUI2 方案。
💡
决策建议：如果你的核心诉求是"安装器好看"，上一版 MUI2 + 侧边图方案（0.5 天工作量，风险极低）已经能达到 70 分。这一版 Fancy 方案（4-5 天，差量更新有风险）能达到 90 分，但投入产出比需要权衡。建议先落地上一版，后续有时间再迭代这一版。
