Trim 安装包与 GitHub 自动更新接入方案

仓库 xiaoxu1642/TuneForge 当前版本 v2.5.0 Electron 44.1.1 electron-builder 26.15.3 分支 main

目标：用 electron-builder 产出 Windows 安装版（NSIS Setup），用 electron-updater 对接 GitHub Releases，实现「启动后台检查 → 提示新版本 → 下载（差量）→ 用户确认 → 退出并静默替换重启」的闭环。 本方案只做设计与代码级落地指引，不直接改动项目源码，确认后按步骤实施。

现状诊断（基于仓库实读）

打包目标

仅 portable 便携版

win.target 只有 portable，便携版在临时目录解压运行，无法走标准 NSIS 替换式自动更新。

运行时依赖

缺少 electron-updater

dependencies 为空，需安装 electron-updater，且必须放在 dependencies（要打进 asar）。

发布配置

缺 repository / publish

package.json 未声明仓库地址与更新源，electron-updater 无从定位 latest.yml。

已就绪

GitHub 远端与规范齐备

origin 已指向 TuneForge，main 分支、历史 tag v2.0.0；IPC 白名单与统一弹窗规范可直接复用。

核心结论：新增 NSIS 安装版，与便携版并存

新增 nsis target 作为可自动更新的正式安装版（产物 Trim-Setup-x.y.z.exe）； 现有 portable target 保留，继续服务绿色版用户（仅手动下载新版，不接入自动更新）。 安装方式选 每用户安装（perMachine: false），配合项目已有的 asInvoker 权限级别，整套下载替换流程 不弹 UAC。

自动更新全链路

electron-updater 不访问 GitHub API，而是直接下载 Release 资产里的静态清单 latest.yml； 完整性由清单内的 SHA-512 保证，不依赖代码签名证书。

应用启动窗口就绪后延迟 8s 静默检查；设置页可手动检查
拉取 latest.ymlreleases/latest/download/latest.yml，含版本号/哈希/包名
SemVer 比对2.5.1 > 2.5.0 才提示；相同/更低则静默结束
差量下载blockmap 分块比对，仅拉变化块，失败回退全量
SHA-512 校验与 latest.yml 记录不符则丢弃安装包并报错
暂存安装包下载到用户目录缓存，等待用户确认，不强制退出
quitAndInstall用户确认后退出，NSIS 静默覆盖安装（含 finder.exe 等资源）
自动重启新版本启动，app.getVersion() 即为新版本号

更新清单的固定地址：https://github.com/xiaoxu1642/TuneForge/releases/latest/download/latest.yml， 浏览器直接打开能下载到该文件，即代表发布侧结构正确。

3 新增 src/main/updater.js：autoUpdater 封装状态全部事件化推给渲染层，主进程不弹原生框
js · src/main/updater.js（新增）
// src/main/updater.js — 应用自动更新（electron-updater + GitHub Releases）
// 批次：自动更新接入
// 约束：
// 1) 仅打包后生效（app.isPackaged），开发环境 npm start 直接短路；
// 2) 状态全部经事件推给渲染层，由统一弹窗服务呈现，主进程不弹原生 dialog；
// 3) 下载完成不强制退出：用户确认后才 quitAndInstall，避免打断清理/测速任务；
// 4) 更新源来自打包时自动生成的 resources/app-update.yml。
const { autoUpdater, CancellationToken } = require('electron-updater');
const { app } = require('electron');

let winRef = null;
let writeLog = () => {};
let cancelToken = null;
let started = false;

// 统一向主窗口渲染层推送状态（phase 见第 04 节状态机）
function push(state) {
  try { winRef?.webContents?.send('updater:state-changed', state); } catch (_) {}
}

function normalizeNotes(notes) {
  if (!notes) return '';
  if (typeof notes === 'string') return notes;
  if (Array.isArray(notes))
    return notes.map(n => n.note || n.title || '').filter(Boolean).join('\n');
  return String(notes);
}

// mainWindow：主窗口引用；logger：项目现有 writeLog(level, msg)
function initUpdater(mainWindow, logger) {
  if (started) return;
  started = true;
  winRef = mainWindow;
  if (typeof logger === 'function') writeLog = logger;

  if (!app.isPackaged) {
    writeLog('info', '[updater] 开发环境，跳过自动更新');
    return;
  }

  autoUpdater.autoDownload = false;       // 发现新版先问用户，不偷跑流量
  autoUpdater.autoInstallOnAppQuit = true; // 已下载完时，退出应用顺手安装
  autoUpdater.logger = {
    info: m => writeLog('info', `[updater] ${m}`),
    warn: m => writeLog('warn', `[updater] ${m}`),
    error: m => writeLog('error', `[updater] ${m}`),
    debug: () => {}
  };

  autoUpdater.on('checking-for-update', () => push({ phase: 'checking' }));
  autoUpdater.on('update-available', info => {
    writeLog('info', `[updater] 发现新版本 ${info.version}（当前 ${info.currentVersion}）`);
    push({ phase: 'available', version: info.version,
      currentVersion: String(info.currentVersion),
      releaseNotes: normalizeNotes(info.releaseNotes), releaseDate: info.releaseDate });
  });
  autoUpdater.on('update-not-available', info =>
    push({ phase: 'latest', currentVersion: info?.currentVersion?.version || '' }));
  autoUpdater.on('download-progress', p => push({
    phase: 'downloading', percent: Math.round(p.percent || 0),
    speed: p.bytesPerSecond || 0, transferred: p.transferred || 0, total: p.total || 0
  }));
  autoUpdater.on('update-downloaded', info =>
    push({ phase: 'ready', version: info.version }));
  autoUpdater.on('error', err => {
    writeLog('error', `[updater] ${err?.stack || err}`);
    push({ phase: 'error', message: err?.message || String(err) });
  });

  // 启动 8s 后静默检查一次：避开窗口动画与概览预热的资源抢占期
  setTimeout(() => safeCheck(true), 8000);
}

// silent=true：网络失败/无新版都不打扰用户（启动后台检查用）
async function safeCheck(silent = false) {
  if (!app.isPackaged) return { skipped: true, reason: 'dev' };
  try {
    await autoUpdater.checkForUpdates();
    return { ok: true };
  } catch (e) {
    writeLog('error', `[updater] 检查失败: ${e.message}`);
    if (!silent) push({ phase: 'error', message: e.message });
    return { ok: false, error: e.message };
  }
}

async function startDownload() {
  if (cancelToken) return { ok: false, error: 'already-downloading' };
  cancelToken = new CancellationToken();
  try {
    await autoUpdater.downloadUpdate(cancelToken);
    return { ok: true };
  } catch (e) {
    cancelToken = null;
    writeLog('error', `[updater] 下载失败: ${e.message}`);
    push({ phase: 'error', message: e.message });
    return { ok: false, error: e.message };
  }
}

function cancelDownload() {
  try { cancelToken?.cancel(); } catch (_) {}
  cancelToken = null;
  push({ phase: 'idle' });
}

function installUpdate() {
  writeLog('info', '[updater] 用户确认安装，退出并执行替换');
  // isSilent=true 由 NSIS 静默安装；isForceRunAfter=true 安装完自动重启 Trim
  autoUpdater.quitAndInstall(true, true);
}

module.exports = { initUpdater, safeCheck, startDownload, cancelDownload, installUpdate };

// src/scripts/updater-ui.js — 自动更新渲染层状态机
// 约束：复用 modal.js 统一弹窗；所有文本走 textContent（禁拼 HTML）；
// window.api 缺失时优雅降级（与 ds 未加载兜底一致）。
(function () {
  'use strict';
  const state = { phase: 'idle', percent: 0, version: '', message: '' };
  let unbind = null;

  // phase: idle/checking/available/latest/downloading/ready/error
  // 按 phase 切换弹窗：检查中转圈、available 显示版本与更新日志+「下载」、
  // downloading 显示百分比进度条与「取消」、ready 显示「立即重启」、latest 提示已是最新
  function render() {
    // TODO(实施): 用 ds.js 现有 modal/进度条组件重绘，全部 textContent 赋值，
    // 进度条宽度 = state.percent + '%'，不要用 innerHTML 拼字符串
  }

  async function checkManual() {
    await window.api.updater.check(); // 状态由 onState 回流驱动 render
  }

  document.addEventListener('DOMContentLoaded', () => {
    if (!window.api?.updater) return; // 优雅降级
    unbind = window.api.updater.onState(s => { Object.assign(state, s); render(); });

    document.addEventListener('click', (e) => {
      const act = el => e.target.closest(el);
      if (act('[data-action="check-update"]')) checkManual();
      if (act('[data-action="download-update"]')) window.api.updater.download();
      if (act('[data-action="cancel-update"]')) window.api.updater.cancelDownload();
      if (act('[data-action="install-update"]')) window.api.updater.install();
    });
  });

  window.addEventListener('beforeunload', () => { try { unbind?.(); } catch (_) {} });
})();

更新状态机（主进程 phase → 渲染层 UI）

updater.js 只推一个字段 phase 加负载数据，渲染层据此切换弹窗形态，避免多通道状态错乱。

idle
初始/取消后归位，不显示
checking
正在请求 latest.yml，弹窗显示转圈
available
发现新版，显示版本/更新日志/「下载」
latest
已是最新版，手动检查时轻提示
downloading
percent 0→100，进度条+速率+「取消」
ready
校验完成已暂存，显示「立即重启」
error
失败原因文本；后台静默检查不弹此态
checking手动/8s 定时
available ?SemVer 判定分支
downloading可 cancel 回 idle
readySHA-512 通过
install → restartquitAndInstall

任何阶段网络失败都进 error；启动 8s 的后台检查以 silent 模式调用，error/latest 均不弹窗，只有用户手动点「检查更新」才把结果显性化。

GitHub Releases 发布 SOP

每次发版固定走下面的时间轴。自动与手动二选一，推荐先用手动跑通一次再配自动发布。

T0 · 改版本
提升 package.json 的 version

严格 SemVer 递增，如 2.5.0 → 2.5.1；修复用 patch、新功能用 minor。不递增则客户端比对认为「无新版」。

T+1 · 构建
本地出包

有 Rust 改动先 cargo build --release；随后 npm run build（prebuild 自动执行 gen-fallback）。到输出目录核对三件套。

T+2 · 提交
提交代码并打 tag

git add -A && git commit && git tag v2.5.1 && git push origin main --tags。tag 必须带 v 前缀且与 version 对应。

T+3 · 发布
建 Release 并上传产物（二选一）

方式 A 自动：准备 GitHub Token（PAT 勾选 repo 权限），PowerShell 下 $env:GH_TOKEN="ghp_xxx" 后执行 npm run release，electron-builder 自动建 Release、传全部资产。

方式 B 手动：GitHub 仓库 → Releases → Draft a new release → 选 tag v2.5.1 → 上传 Trim-Setup-2.5.1.exe、.blockmap、latest.yml 三个文件 → Publish release。

T+4 · 验收
确认客户端可收

浏览器打开 releases/latest/download/latest.yml 能下载且 version 为新版；已装旧版的机器点「检查更新」走完全链路。

灰度 · 可选
beta 预发布通道

Release 勾选 Set as pre-release 即成为 beta 通道；客户端需 autoUpdater.channel = 'beta' 才会收到，稳定版用户不受影响，可用于小范围灰度。

三个发布侧高频「收不到更新」原因：

  • Release 保存为 Draft：草稿资产需要登录鉴权，updater 直接 404，必须 Publish；
  • 漏传 latest.yml：客户端没有版本清单可比；
  • tag/version 不一致或没递增：SemVer 判定无新版。

差量更新（blockmap）原理

分块哈希比对

electron-builder 把安装包按约 64KB 切块，对每块算哈希写入 .blockmap。更新时客户端先下载新旧两个 blockmap（仅几十 KB），逐块比对：哈希相同的块跳过，只下载变化块，再本地拼出完整新包。

自动全量兜底

差量拼接失败、块损坏或 blockmap 缺失时，electron-updater 自动回退下载完整 Setup.exe，用户侧只表现为下载量变多，流程不中断。最终都以 latest.yml 的整包 SHA-512 校验为准。

一次典型 2.5.0 → 2.5.1 的流量构成

新旧 blockmap各几十 KB，必下
变化块通常仅占整包 10%~40%（取决于 asar 改动面）
本地拼包旧包缓存块 + 新块合成
SHA-512 整包校验与 latest.yml 一致才允许安装

差量命中率与包结构有关：extraResources 里的 finder.exe、TrimFastSize.dll 若本版未重新编译，其对应块保持不变，不会重复下载；因此没改 Rust 就不要无意义重编 finder.exe，可减小更新包体积。

避坑清单（14 条）

01portable 不支持标准自动更新

便携版每次解压到 %TEMP% 临时目录运行，没有固定安装路径可供 NSIS 覆盖。自动更新只面向 nsis 安装版，便携版保留手动下载。

02依赖放错节点直接崩

electron-updater 必须在 dependencies。devDependencies 不进 asar，打包后 require 抛 MODULE_NOT_FOUND。

03三件套必须同传

latest.yml 负责「发现新版」，.blockmap 负责「差量」，exe 负责「安装」。缺 yml 完全收不到，缺 blockmap 退化为全量。

04Draft 不可见、pre-release 走 beta

草稿要鉴权导致 404；预发布版只有 channel='beta' 的客户端能收到，正式版用户看不到。

05版本号与 tag 规则

SemVer 严格递增（2.5.1>2.5.0），git tag 用 v 前缀（v2.5.1）。两者不一致是最常见的「明明发了却收不到」。

06开发环境必须短路

npm start 时 resources 下没有 app-update.yml，检查必然报错。updater.js 已用 app.isPackaged 短路，不要删这道判断。

07验证必须先装「旧版」

自动更新只对已安装的 Setup 版生效：先安装 2.5.0，再发布 2.5.1，才能在本机看到完整更新链路。

08免 UAC 的组合条件

perMachine:false（装 %LOCALAPPDATA%\Programs）+ asInvoker（项目已配置）。改成 perMachine:true 装 Program Files 后，每次更新都弹 UAC。

09未签名 ≠ 不能更新

完整性由 SHA-512 保证，无需代码签名证书；但未签名安装包首跑有 SmartScreen 信誉提示，属另一回事，后续可再补证书签名。

10国内 GitHub 网络抖动

后台静默检查失败不打扰用户；若普遍超时，可换 generic 源：把三件套放自有静态服务器/对象存储，publish 改为 {"provider":"generic","url":"https://你的地址/updates/win/"}，客户端代码无需动。

11下载完别强退

清理、测速、大文件扫描可能正在运行。autoDownload=false + 用户确认安装；autoInstallOnAppQuit 只在用户正常退出时兜底。

12extraResources 自动跟随

finder.exe、TrimFastSize.dll 已在 build.extraResources，NSIS 安装与更新替换时自动带上，不需要为更新单独处理。

13输出目录含空格

「Trim goujian」目录名带空格，本地 pwsh 脚本路径必须引号包裹；electron-builder 本身不受影响。

14回归测试同步

新增渲染脚本与配置后执行 npm run test（test-features.js 含双源一致性等断言）；改动 JS 一律 node --check。

回滚策略

发布侧回滚（推荐）

新版本出问题：在 GitHub 将该 Release 标记为 Draft 或删除资产（latest.yml 一并下架），客户端随即检查不到新版，停留在旧版本；修复后提升 patch 版本重新发布即可，不要重新发布相同版本号。

用户侧回滚

NSIS 卸载保留用户数据（deleteAppDataOnUninstall:false），用户可卸载新版后安装旧版 Setup；配置、白名单与清理记录不丢失。
