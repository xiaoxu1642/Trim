Trim 安装器视觉升级方案 v3.1

在现有 nsis.include 钩子路线上，把安装器做成薰衣草紫单色系渐变的品牌化安装体验：深紫渐变底 + 光晕 + 渐变主按钮 + 渐变进度条 + 12px 圆角卡片，窗口 640×440，三页流程，卸载器同款。安装/静默/卸载链路仍走 electron-builder 原逻辑，自动更新零风险。

薰衣草渐变 品牌触点放宽 §5 640×440 nsis.include 钩子 零新增依赖 含卸载器

00结论速览

一句话

路线不变（nsis.include 钩子），视觉整体换血：渐变只能出现在预渲染位图与位图按钮上，原生控件（输入框、复选框、进度条本体）仍是纯色 —— 这是 NSIS 的硬边界，方案里已按"渐变白名单"逐项安排。

维度现状（2.5.1 已发布产物）v3.1 目标

01前提与边界

1.1 「必须切 nsis.script 才能做大窗口」→ 不成立

  • MUI2 的外框就是普通 Win32 对话框，运行期用 USER32::MoveWindow 改尺寸即可；官方 Interface.nsh 本身就是用 GetDlgItem $mui.Button.Next $HWNDPARENT 1 拿控件的。
  • 官方还有 MUI_UI 定义（ChangeUI all "${MUI_UI}"），指向自制对话框资源可一次性换外框模板；但需要 Resource Hacker + 对话框单位换算，本方案不采用。
  • 真正需要 nsis.script 的只有「无边框 / 自绘标题栏 / 透明窗口」。要做那一步，得自己重写卸载器、注册表、静默参数、UAC 兜底 —— 与"更好看的安装器"这个目标不成正比。

1.2 只要你还在用应用内自动更新，这三条就是硬约束

单人用户不用管历史版本覆盖，但只要 electron-updater 还在，下面三条必须保持；nsis.include 路线免费拿到它们：

1.3 视觉授权：本次放宽 §5，但只限安装器

与 AGENTS.md §5 的关系

AGENTS.md §5 写的是「设计系统只用 main.css 既有 token；圆角 ≤8px；禁彩色渐变」—— 那条针对的是应用内 UI。安装器是发布触点，本次经你确认，允许使用薰衣草单色系渐变与更大圆角（≤12px），应用内界面一律不动。

放宽范围仅限：渐变、光晕、圆角 ≤12px、按钮投影。仍然不做：窗口透明、无边框、位图之外的动画、第三方 UI 插件/新依赖。

1.4 渐变的三条工程底线

  1. 色彩单色系：只允许薰衣草族（#A6A9F2 → #7174CC）+ 品牌深紫（#171832）之间过渡，禁止出现第二色相（蓝/粉/绿），避免"彩虹感"。
  2. 渐变只落在位图上：24bit BMP 无 alpha，半透明必须提前合成到固定底色；原生控件（输入框/复选框/进度条本体）只能纯色。
  3. 暗底上必须有"分离度"：深紫面上叠深紫卡片会糊，卡片用 rgba(255,255,255,.035) + rgba(139,142,224,.16~.22) 描边提亮（见 2.1）。

04技术实现骨架

以下骨架基于现有 build/installer.nsh 的结构与约束：该文件在 sharedHeader 阶段先于 common.nsh/MUI2.nsh 编译；-WX 下未引用的 Function 会 6010 报错；nsDialogs 每页必须以 nsDialogs::Show 收尾。

4.1 第一步：先量后画（不要凭感觉写坐标）

; 批次 1 临时打点：MUI 外框创建后量尺寸，实测完删除
!define MUI_CUSTOMFUNCTION_GUIINIT TrimGuiProbe

Function TrimGuiProbe
  System::Alloc 16
  Pop $R0
  System::Call 'USER32::GetClientRect(p $HWNDPARENT, p $R0)'
  System::Call '*$R0(i .r1, i .r2, i .r3, i .r4)'   ; 客户区 = $3 × $4
  System::Free $R0
  GetDlgItem $9 $HWNDPARENT 1018
  System::Alloc 16
  Pop $R1
  System::Call 'USER32::GetClientRect(p $9, p $R1)'
  System::Call '*$R1(i .r1, i .r2, i .r5, i .r6)'   ; 页面区 = $5 × $6
  System::Free $R1
  MessageBox MB_OK "outer client=$3 x $4$\npage(1018)=$5 x $6"
FunctionEnd

在 100% / 125% / 150% 三档缩放下各量一次，把页面区尺寸写回生成器的 PAGE_W, PAGE_H，保证位图 1:1 不拉伸 —— 这是"渐变看起来高级而不是糊"的第一前提（渐变被拉伸时最容易出现色带）。

4.2 放大窗口 + 平移底部控件

Var Trim.OrigW
Var Trim.OrigH
!define TRIM_W 640     ; 目标客户区宽
!define TRIM_H 440     ; 目标客户区高（含底部 52px 按钮条）

!define MUI_CUSTOMFUNCTION_GUIINIT TrimGuiInit

Function TrimGuiInit
  ; ① 记录原始客户区（后续算位移，禁止写死像素）
  !insertmacro TRIM_GET_CLIENT $HWNDPARENT $Trim.OrigW $Trim.OrigH

  ; ② 外框尺寸 = 目标客户区 + (当前外框 − 当前客户区)
  !insertmacro TRIM_GET_WINDOW $HWNDPARENT $R7 $R8
  IntOp $R7 $R7 - $Trim.OrigW
  IntOp $R8 $R8 - $Trim.OrigH
  IntOp $R7 $R7 + ${TRIM_W}
  IntOp $R8 $R8 + ${TRIM_H}

  ; ③ 居中并一次性 MoveWindow
  System::Call 'USER32::GetSystemMetrics(i 0) i .r1'   ; SM_CXSCREEN
  System::Call 'USER32::GetSystemMetrics(i 1) i .r2'   ; SM_CYSCREEN
  IntOp $R5 $r1 - $R7
  IntOp $R6 $r2 - $R8
  IntOp $R5 $R5 / 2
  IntOp $R6 $R6 / 2
  System::Call 'USER32::MoveWindow(p $HWNDPARENT, i $R5, i $R6, i $R7, i $R8, i 0)'

  ; ④ 底部控件按 (dx,dy) 平移：下一步(1)/取消(2)/上一步(3)/品牌文字(1028,1256)
  IntOp $R1 ${TRIM_W} - $Trim.OrigW
  IntOp $R2 ${TRIM_H} - $Trim.OrigH
  !insertmacro TRIM_SHIFT_CTRL 1 $R1 $R2
  !insertmacro TRIM_SHIFT_CTRL 2 $R1 $R2
  !insertmacro TRIM_SHIFT_CTRL 3 $R1 $R2
  !insertmacro TRIM_SHIFT_CTRL 1256 $R1 $R2

  ; ⑤ 页面区（1018）与自绘页由现有 TrimFullBleed 按新客户区自动铺满
  !insertmacro TRIM_DARK_TITLEBAR
FunctionEnd

TRIM_SHIFT_CTRL 的稳妥写法：GetWindowRect(控件) → ScreenToClient($HWNDPARENT, 左上角) → 加 (dx,dy) → MoveWindow。必须用相对位移，这样 125%/150% 下按钮不会跑到窗口中间。

4.3 深色标题栏（配深紫主题）

!macro TRIM_DARK_TITLEBAR
  System::Alloc 4
  Pop $R0
  System::Call '*$R0(i 1)'
  ClearErrors
  System::Call 'dwmapi::DwmSetWindowAttribute(p $HWNDPARENT, i 20, p $R0, i 4)'  ; Win10 1903+
  ${If} ${Errors}
    ClearErrors
    System::Call 'dwmapi::DwmSetWindowAttribute(p $HWNDPARENT, i 19, p $R0, i 4)' ; Win10 1809
  ${EndIf}
  System::Free $R0
  ClearErrors
!macroend

4.4 渐变与控件的能力边界（别在不可能的地方花时间）

4.5 完成页统计（文件数 / 大小 / 耗时）

; ① customInit（.onInit 期）记录起始 tick
System::Call 'kernel32::GetTickCount() i .r0'
StrCpy $Trim.StartTick $R0

; ② 完成页 TrimFinishPre 内计算（FileFunc.nsh 只放 installer pass）
!include FileFunc.nsh        ; 必须在 !ifndef BUILD_UNINSTALLER 内，避免卸载器 pass 6010
${GetSize} "$INSTDIR" "/S=0K" $0 $1 $2      ; $0 = 总 KB

4.6 渐变主按钮（本方案核心，非可选）

渐变的三个工程要点

  • 先渐变、后文字：先画渐变底，再叠文字/描边，最后 2× → 1× 降采样，文字边缘才不会带渐变杂边。
  • 防色带：暗色渐变在 8bit/通道下容易出现条带。手段：起止色差控制在小范围（本次 #20214A → #171832 跨度已足够小）、2× 超采样、必要时加 ±1 的抖动（dither）。
  • 无 alpha：BMP 24bit 没有透明通道，所有"半透明"必须预先合成到确定的底色；这就是为什么卡片/按钮要用固定底板而不是叠加在动态背景上。

10.1 实测踩坑（重做时不要再踩）

坑现象与结论
include 的 .nsh 必须带 UTF-8 BOM无 BOM 时 NSIS 按本地代码页解码 !include 文件，中文注释会把后续行吞掉，报出与真实原因无关的错（本次报的是 Usage: StrCpy，实际是解析错乱）。结论：build/installer.nsh 一律用 UTF-8 with BOM 保存。
nsDialogs 坐标单位实测像素；u 后缀在这版 nsDialogs 里无效（带 u 的控件直接不渲染）。位图按像素出图即可 1:1。
背景位图控件会盖住后建的控件铺满整页的 STATIC 位图若不压 z 序，会覆盖后创建的标签/按钮/勾选框（EDIT 例外）。结论：创建完所有控件后 SetWindowPos $Bg HWND_BOTTOM。
按钮贴图用错消息STM_SETIMAGE(0x172) 只对 STATIC 有效；BUTTON 必须用 BM_SETIMAGE(0x00F7)。另外运行期 SetWindowLong 追加 BS_BITMAP 在该版本无效 —— 按钮必须在创建时就带 BS_BITMAP（底部原生按钮走「隐藏原生 + 位图静态层转发点击」或保持原生）。
寄存器混用System::Call 的输出写进 $1..$9，与 $R1..$R9 不是一回事；本次窗口尺寸算错（646×469 变 1354×804）就是这个原因。
-WX 下的变量规则使用了未声明的变量、或声明了未引用的变量都会导致编译失败（6010/6001）。改造后用脚本核对「声明集合 = 引用集合」。
