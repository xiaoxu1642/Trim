# Trim v2.7.1 更新说明（2026-09-13）

> 用户反馈驱动的体验修补版：启动页视觉融合与编排加速、关闭后自动清旧包政策。

---

## 一、右上角原生按钮区在启动页期间的割裂（修复）

- **原因**：右上角最小化/最大化/关闭是 Windows 原生 `titleBarOverlay`（非客户区），由系统在网页内容之上绘制——DOM 元素无论 z-index 多大都盖不住它，这是浏览器窗口的层级设计，不是 bug。
- **修复（融合方案）**：启动页期间主进程 `setTitleBarOverlay` 把覆盖层背景临时染成启动页渐变顶色 `#efedfb`，右上角按钮区视觉上融入启动页；落位结束恢复正式色 `#f7f8fb`。新 IPC `splash:overlay`（preload `window.api.window.setSplashOverlay`），splash.js 首尾各调一次，无 API 时优雅降级。

## 二、落位编排：内容渐显（v2.7.0 遗留的突兀揭幕修复)

- 启动页自身底色改为**透明**（原为不透明白，揭幕瞬间生硬）：进入过渡时 `.splash-bg` 渐变层淡出，**主界面在 Trim 平移的同时渐显**（实测不透明度序列 1 → 0.68 → 0.18 → 0.018 → 0）。
- 默认落在**系统体检页**（`page-overview` 本就是默认激活页，无路由改动）。

## 三、启动「墨迹」问题：结论与替代方案

- **结论：Rust 加速不了启动**。启动耗时构成 = Chromium/Electron 进程链启动 + 渲染层脚本解析 + PowerShell/WMI 首次查询（1.5s 指标预热、3s 优化扫描已错峰后台化）。这三样都不是纯计算瓶颈：前两者是框架固有成本，后者是外部进程冷启动——Rust 只能加速自家代码里的纯计算（如 finder.exe 扫描），对启动链路无可下手；把 UI 换成 Rust 框架（Tauri）等于推翻重来，此前已从 Tauri 迁出，不可取。
- **已落地的替代方案**：
  1. **真实进度替代假进度**：app.js 初始化完成派发 `trim:boot-ready`，启动页进度条到 92% 后停在原地等真实就绪，就绪即收尾进入——进度条不再「走完了还在等」；
  2. **节奏压缩**：首访 2400→1600ms、紧凑模式 900→500ms、落位动画 900→750ms、进入延迟 400→150ms；紧凑模式（日常启动）从点开到可用约 **1.5s**（原约 2.4s）；
  3. 兜底不变：4s 等不到就绪事件照常进入、15s 硬兜底、reduced-motion 直进主界面。

## 四、构建政策：新包建成自动清旧包

- `npm run build` 接入 **postbuild 钩子**（`scripts/clean-old-packages.js`）：构建完成后自动把 `build-release/` 里所有**非当前版本**的 Setup/Portable 安装包及 blockmap 移入回收站（可还原；回收站不可用才降级永久删除），`latest.yml`、`win-unpacked/` 等当前构建产物不动。
- 当前版本文件受保护（按 package.json version 比对），清理失败不阻塞构建但以非零退出码可见。
