## 二、两个项目提供、而 Trim 缺失的功能（按优先级）

### P0 · 高价值、与 Trim 定位契合、实现成本可控

**【原型】重复文件查找**
- 按文件名 / 体积 / Hash（xxhash）三层去重，可一键选择保留副本并删除多余项。
- 磁盘释放收益直接，是"空间不够"场景下最常被要的功能。
- 落地：新增"重复文件"模块，先用 PowerShell `Get-FileHash`（可加 `-Algorithm SHA256`）对指定目录抽样/全量扫描，文件体积再哈希；数据量极大时可在后续替换为 Rust/PowerShell 双实现的 native 扫描器。

**【原型】大文件（最大文件）查找**
- 在给定位置列出前 N 个最大文件（默认 50），按体积排序展示，支持目录大小汇总。
- Trim 曾有此功能但被移除，属"回归补强"。
- 落地：直接复用 `optimizer-scripts.js` / `cleanup` 的扫描输出管线，新增"空间分析"页签，展示 Top-N 大文件 + 各目录占用占比（配简易 treemap）。

**【参考实现】AppData 大文件夹扫描 + 跨盘迁移 + Junction 目录联接**
- 扫描 `%LOCALAPPDATA%` / `%APPDATA%`，找出占用超过阈值（默认 10%）的大户；勾选后将文件夹整体迁移到目标盘，并在原位创建 `mklink /J` 目录联接，软件零感知继续运行。
- 直接解决 "C 盘满了" 且不想删数据的场景，与 Trim"磁盘清理"互补（清理=删，迁移=搬）。
- 落地：新增"AppData 瘦身"模块；PowerShell 实现 `第? 步`：扫描大小 → 用户选目标盘 → `robocopy /MIR` 迁移 → `New-Item -ItemType Junction`（或 `cmd /c mklink /J`）→ 校验。需管理员权限，与 Trim 现有提权链路一致。

**【原型】空文件夹 / 空文件查找**
- 用算法找出空目录、空文件并删除（快速释放大量小碎片）。
- 落地：`Get-ChildItem -Recurse` 过滤 `Length -eq 0` / 无子项目录，预览后删除；实现简单。

### P1 · 中等价值 / 工作量

**【原型】临时（垃圾）文件按扩展名扫描**
- 按扩展名/命名规则找出 `*.tmp`、`~$*`、`Thumbs.db`、`*.log`、`*.old`、`*.bak` 等，比现有"磁盘清理"更贴近"文件级精确清理"。
- 部分与现有 `cleanup-rules.json` 重叠，方案：在磁盘清理中增加"扩展名规则"一键项作为补充，而非新建模块。

**【参考实现】文件占用自动结束进程（Restart Manager）**
- 迁移/删除前用 Windows Restart Manager 查询占用进程并自动结束，提升清理成功率。
- 落地：在"磁盘清理/AppData 迁移"执行被占用文件前，先 `获取占用进程 -> 提示 -> 结束`；PS 中可用 `openfiles` 或遍历句柄的工具实现轻量版。

**【原型】失效快捷方式 / 损坏文件检查
- 找出指向不存在目标的快捷方式（`.lnk`），与损坏文件（图片/视频/压缩包头校验失败）。
- 落地：`.lnk` 用 `WScript.Shell` 解析 TargetPath 判存在性；损坏文件做头部魔数抽查。中低成本。

### P2 · 低优先级 / 实现重 / 价值有限

**【原型】相似图片 / 相似视频 / 相似音乐**
- 感知哈希 / 标签匹配查找"相似但不同"的媒体；对视频/图片要依赖 OpenCV/ffmpeg，体积与成本高，且 Trim 定位是"系统优化"而非媒体管家 → **本轮不做**，可作为远期扩展栏位。

**【原型】可疑文件 / 坏扩展名 / 坏文件名**
- 内容与扩展名不符、含特殊字符的文件；属安全类，实用面窄 → 低优先级。

**【原型】视频优化压缩**
- 依赖 ffmpeg 转码，超出系统优化范畴 → 不建议加入。

## 三、建议落地路线（对齐 Trim 现有架构）

所有新功能尽量复用既有执行模型，避免引入新技术栈：

1. **统一放"清理 / 空间管理"分组**：现有 `磁盘清理` 之下新增页签：`重复文件`、`大文件/空间分析`、`空文件与空目录`、`AppData 瘦身`；样式复用 `.card / .table-card / .opt-*`，沿用布尔进度 + `@@PROGRESS:n@@` 上报管线。
2. **扫描脚本全部放 `scripts-powershell\`**（如 `finder-scripts.js`），遵循"记录注册表/操作前备份、可回滚"的既有铁律；删除类操作一律先入回收站或二次确认。
3. **权限与安全**：AppData 迁移、占用进程结束需管理员，沿用 `btnOptimizerElevate` 链路；大扫描可加"取消/暂停"（复用原型工具的增量/缓存思路）。
4. **性能兜底**：全盘哈希扫描在 PowerShell 下较慢，第一版提供"目录范围选择 + 体积分层（如 >50MB 才哈希）"；后续若需全盘 80GB+ 级扫描，再评估引入 Rust 二进制（可复用 参考实现 的 crates）。
5. **本地简介联动**：新条目同步写入 `src/data/item-intro.json` 的 `optimizer.byId` 或新增 `finder` scope，保持离线简介完整（见 `docs/优化脚本本地简介.md` 的生成方式）。

### 上线顺序建议
- **第一批（最快见效）**：AppData 瘦身迁移、大文件/空间分析、空文件夹与空文件。
- **第二批**：重复文件查找、失效快捷方式、扩展名垃圾清理补充。
- **第三批（按需）**：EXIF 清理、损坏文件检查。
- **暂缓**：相似媒体、视频压缩、可疑文件。

## 四、参照实现要点

- **AppData 迁移 + Junction**（参考 `feiqi\1、\src\core\mover.rs`）：
  - 步骤：`robocopy {src} {dst} /MIR /MT /R:1 /W:1` → 删除原位 → `cmd /c mklink /J "{src}" "{dst}"` → 复检目录受影响。
  - 关键：先传 `ScanResult`（路径+大小+占用进程）→ 用户勾选 → 逐步 `MoveStart/MoveProgress/MoveComplete` 事件上报（与 Trim 进度管线同构）。
- **重复文件**（参考 `参考实现_core\tools\duplicate\`）：先按 **文件大小分组**，仅对同体积组做哈希，可把比对量降到个位数百分比。
- **空目录/空文件**：`Get-ChildItem` 后按 `LastWriteTime` 排序，优先清最久未访问的，提示用户后回收站删除。
