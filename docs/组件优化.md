\## 一、项目背景

\- 产品定位：Windows 11 原生风格的系统清理与优化桌面工具（类似火绒/CCleaner），仅支持 Windows 11 22H2+

\- 技术栈：Electron 桌面容器；前端是原生 HTML/CSS/JavaScript 实现 Fluent Design，不依赖任何前端框架；系统层用 PowerShell 7 调用 Windows API

\- 核心模块：系统概览、磁盘清理、内存清理、电脑优化中心、启动项管理、右键管理、磁盘/网络测速、实时网速、系统还原点、操作日志、全局设置



\## 二、UI 约束（筛选硬标准）

1\. 视觉风格必须贴合 Windows 11 Fluent Design：深色主题用 carbon ladder 色阶、浅色主题标题色 #1c1e24 正文色 #4b505b，满足 WCAG 对比度

2\. 窗口材质使用 Mica / Acrylic，组件需支持半透明、毛玻璃、柔和高斯模糊的视觉适配

3\. 所有按钮统一 ripple 波纹动效；系统开启「减弱动效」时不创建动效 DOM

4\. 高风险操作必须有红色二次确认弹窗；操作过程需展示进度反馈

5\. 组件风格偏「系统工具感」而非「网页后台感」，避免圆角过大、卡片过重、彩色渐变泛滥



\## 三、任务要求

对上面每个核心模块，分别从 antd 和 shadcn/ui 中推荐 1-3 个最合适的组件，并说明：

1\. 组件名与所属库（antd / shadcn/ui）

2\. 用在哪几个模块、解决什么交互

3\. 为什么契合 Trim 的 Fluent 风格（视觉契合度打分 1-5）

4\. 定制难度：改成 Fluent 风格需要多大工作量（低/中/高）

5\. 落地方式：由于项目是原生 JS，请明确说明是「直接借鉴交互逻辑用原生重写」还是「建议引入 React 局部使用」，并给出理由

6\. 体积/性能影响：是否值得引入，有没有更轻量的原生替代方案



\## 四、输出格式

按「模块 → 推荐组件对比表 → 最终建议」组织，最后单独给出一个「整体结论」：如果只能选一个库作为主要参考，选 antd 还是 shadcn/ui，为什么。
